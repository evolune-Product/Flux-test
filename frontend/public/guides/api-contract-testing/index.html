API Contract Testing

What is Contract Testing?

Contract testing ensures that service providers (APIs) meet the expectations of consumers (frontends, other services). It validates that API contracts don't break when providers change.

The Problem Contract Testing Solves

Scenario: Backend team changes user API response from {"name": "John"} to {"first_name": "John", "last_name": "Doe"}

Result: Frontend breaks because it expects name field

Solution: Contract testing catches this before deployment

How Contract Testing Works in Flasqo

  1. Define consumer expectations: Frontend expects GET /users/:id to return {id, name, email}
  2. Provider implements API: Backend creates endpoint
  3. Flasqo validates contract: Does provider response match consumer expectations?
  4. Breaking change detected: Provider removed name field → Test fails
  5. Safe deployment blocked: Fix contract violation before deploying

Contract Testing vs Integration Testing

  • Integration Testing: Tests entire flow end-to-end (slow, flaky)
  • Contract Testing: Tests only interface between services (fast, reliable)

Use Cases

  • Microservices architecture (multiple teams, services)
  • API versioning (ensure v1 stays compatible while building v2)
  • Third-party API integration (validate their API matches docs)
  • Frontend-backend coordination (catch breaking changes early)

Example Contract

Consumer Contract:

GET /products/:id
  • Status: 200
  • Body: {id: number, name: string, price: number}

Provider Test: Flasqo calls endpoint, verifies response matches contract
